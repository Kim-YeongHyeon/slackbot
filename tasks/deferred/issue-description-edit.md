# Deferred — 이슈 본문 수정 (키 지정)

> **등록일:** 2026-05-15
> **우선순위:** 중간
> **요청자:** 사용자 요청

## 배경

현재 본문 수정은 이슈 스레드 안에서만 가능 (`@지라 수정 ~~~` → appendDescription).
이슈 키를 직접 지정해서 채널 어디서든 본문을 수정하는 기능이 필요.

## 요구사항

### 사용법
```
@지라 본문수정 1914 왜 발생했나 (근본 원인) ~~~~
@지라 본문수정 ES2-1914 왜 발생했나 (근본 원인) ~~~~
```

### 동작 모드
1. **덧붙이기** (기본): 기존 본문 끝에 내용 추가 — 현재 `appendDescription()` 재사용
2. **덮어쓰기**: 본문 전체를 새 내용으로 교체 — `@지라 본문교체 1914 ~~~`

### 이슈 키 파싱
- `1914` → 프로젝트 키 자동 보완 (`ES2-1914`)
- `ES2-1914` → 그대로 사용

## 현재 구현 상태

| 기능 | 상태 | 위치 |
|------|------|------|
| 스레드 내 덧붙이기 | ✅ 완료 | `executeModify()` → `appendDescription()` |
| 키 지정 덧붙이기 | ❌ 미구현 | |
| 키 지정 덮어쓰기 | ❌ 미구현 | JiraApiClient에 `replaceDescription()` 필요 |

## 구현 계획

### 1. 키워드 라우팅 추가 (`routeCommand`)
- `본문수정`, `본문추가` → 덧붙이기 모드
- `본문교체` → 덮어쓰기 모드
- 패턴: `본문수정 {이슈번호} {내용}`

### 2. JiraApiClient 확장
- `replaceDescription(String issueKey, String newText)` 추가
- 기존 `appendDescription()` 재사용 (덧붙이기)

### 3. 이슈 키 파싱 유틸
- 숫자만 입력 시 프로젝트 키 자동 보완 (`jiraProps.project()` + "-" + 번호)
- 이미 `PROJ-` 형태면 그대로 사용

## 고려사항

- 덮어쓰기 시 확인 절차 필요 여부 (기존 내용 유실 위험)
- Jira ADF(Atlassian Document Format) 처리: 현재 appendDescription이 ADF paragraph 추가 방식
- 긴 내용 입력 시 Slack 메시지 길이 제한 (4000자)
